# Budget the context a session starts with

Use an inject for orientation or discipline worth carrying throughout the selected session.
It spends context before the current task is known.
Judge its value for the intended profile.

**Check what gets selected**

[[mcp.inject::au-mcp-sdk:example]] declares available context.
Inclusion depends on:

- Owner role
- Profile
- Launch selection

Entry and editable members contribute to the default set.
Dependency and discovery members offer context that can be selected.
A dependency alone does not deliver every inject.

**Match delivery to need**

- Use a skill for instructions tied to a recognizable task
- Use an on-demand guide for a decision the builder can seek during work
- Use a session-start hook for context computed from fresh state at session open

These can coexist.
A short orientation can point to deeper task guidance.

**Budget the expansion**

Inspect the expanded content, not just the seed file.
Reference depth can pull in changing neighbors.
Choose edge kinds deliberately and supply the required filter for walks beyond one hop.
Read the actual expansion and launcher report.

**Inspect the intended harness**

Packing differs by adapter.
Claude Code's generated slots and Codex's runtime context files do not imply equal caps or refresh behavior.
Check selected and omitted content before relying on a “nothing drops” promise.

Launch the intended profile and inspect the complete generated context.
Each block should justify its standing cost.
The output should contain what the workflow depends on.
